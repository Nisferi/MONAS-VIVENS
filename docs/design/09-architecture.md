# 09 — Программная архитектура

> Карта модулей и контракты между ними. Это технический канон проекта.
> Связанные блоки: [10-mvp-plan](10-mvp-plan.md), [05-future](05-future.md).

Архитектура — модульная, каждый модуль изолирован и тестируем отдельно.
Зависимости направлены строго снизу вверх: ничто в ядре не знает про UI.

## Карта модулей

```

  grid.ts        — поле 64×64, типы клеток, тики
  rules.ts       — Ме: законы соседства (пороги рождения/выживания)
  energy.ts      — энергия поля, расход и приток
  decay.ts       — смерть, распад, очистка
phi/         ← измерение сознания
  clusters.ts    — поиск устойчивых кластеров (connected components)
  philia.ts      — подсчёт связности внутри кластеров
  mnemosyne.ts   — возраст стабильности кластеров
  chaos.ts       — учёт мерцающих одиночек
  neikos.ts      — накопление напряжения; правило «Нейкос > 0»
  phi.ts         — итоговая формула Φ
lens/        ← система линз
  lens1.ts       — рендер клеток + интерфейс Ме
  lens2.ts       — свёртка кластеров в узлы, рендер графа связей
  lens3.ts       — рендер целого, Φ, горизонт будущего
  switcher.ts    — переключение линз, условия открытия
future/      ← детерминированное будущее
  forecast.ts    — fast-forward копии движка на N тиков
  horizon.ts     — N = f(Φ): дальность и «туманность» прогноза
  threat.ts      — детерминированная угроза партии (заложена в seed)
tablets/     ← Таблички Судеб
  conditions.ts  — 3 условия (Φ<X, энергия<Y, Хаос>Z)
  actions.ts     — 3 действия (разорвать, спячка, пожертвовать)
  engine.ts      — спящие правила, проверка и срабатывание
  cost.ts        — цена высечения (ресурс сейчас vs. будущее)
run/         ← петля партии
  setup.ts       — биомы, архетипы, seed
  stages.ts      — фазы Genesis → Морфогенез → Разум
  endings.ts     — определение концовки по итоговому состоянию
  score.ts       — формула счёта
  chronicle.ts   — Глиняная летопись из шаблонов
ui/          ← интерфейс
  canvas.ts      — отрисовка поля (один Canvas, три режима)
  hud.ts         — Φ-счётчик, кнопки линз, панель Ме
  tabletUI.ts    — дропдауны Табличек Судеб
  screens.ts     — старт, финал, летопись
platform/    ← обвязка платформ
  telegram.ts    — Telegram Mini App SDK
  storage.ts     — локальные сохранения (seed, рекорды)
  pwa.ts         — манифест, офлайн
[пост-MVP]
multiplayer/  — Weekly Seed, лидерборд, Ghost Worlds, Fossil Archive
dreams/       — сон разума, пророческие сны
memory/       — травма, память vs забывание
board/        — нарративная рамка «знаков эпох» (наследие Twenty Laws)
```

## Ключевые контракты между модулями

- `core` ничего не знает ни о ком. Вход: состояние + Ме. Выход: новое состояние.
  Чистая функция `tick(state, rules) → state` — это даёт бесплатно и прогноз
  (`future/forecast` гоняет тот же `tick`), и реплеи, и детерминизм по seed.
- `phi` читает состояние, возвращает число и разбивку. Не пишет ничего.
- `tablets/engine` — единственный, кто меняет состояние «извне» правил, и только
  по сработавшему условию.
- `ui` читает всё, не считает ничего.

Это правило («ядро — чистые функции») — главное архитектурное решение. Оно делает
возможным детерминированное будущее без отдельного кода.

## Технические требования

- TypeScript strict, без фреймворка в ядре.
- Симуляция в `requestAnimationFrame` с фиксированным шагом логики
  (например, 10 тиков/сек, отрисовка 60 fps).
- Прогноз — в Web Worker, чтобы не подвешивать UI на слабых телефонах.
- Сериализация состояния в JSON (сохранения, seed, будущий обмен мирами).
- Размер бандла MVP — цель < 500 КБ (важно для ТГ Mini App).
